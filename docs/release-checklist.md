# Public Release Checklist

A public release is a separate publication decision, not an automatic consequence of finishing a lab privately.

## Evidence and reproducibility
- [ ] The exact source files and outputs were reviewed in the private workspace.
- [ ] Notebook or script was actually run in the documented environment.
- [ ] Output images, tables, metrics and claims match retained evidence.
- [ ] Reproduction steps, dependencies, parameters and limitations are documented.
- [ ] Notebook outputs are genuine; no placeholder or invented result is presented as measured.

## Privacy and academic integrity
- [ ] User explicitly approved this release.
- [ ] Course rules and assessment timing permit publication.
- [ ] No original lecturer Word templates, lecturer-owned slides, speaker notes, private instructions or private repository paths are included.
- [ ] No student ID, personal identifiers, credentials, tokens or local proxy settings are included.
- [ ] AI assistance is disclosed if required by institutional policy; authorship is represented honestly.

## Asset licensing
- [ ] Every external image, dataset, code fragment and third-party dependency has a provenance/licence review.
- [ ] AI-generated showcase assets are labelled as generated and are not represented as real evidence.
- [ ] Synthetic fixtures are identified as synthetic and used for controlled tests.
- [ ] Asset manifest includes filename, dimensions, purpose, provenance/generation note, licence/attribution and SHA-256.

## Release manifest
- [ ] The exact approved files are listed in publication/manifest.yml.
- [ ] Only those reviewed files are copied into this independent public repository.
- [ ] Public diff and secret scan pass.
- [ ] No automatic bulk mirror from the private workspace is used.
